RETROAPPLEJS · EXPERIMENTAL PAY-00.5

PAY Interpreter

PSID → static disassembly + bounded 6502 runtime / self-modifying-code trace → GPT-assisted musical interpretation. Self-contained browser tool; no external JavaScript or framework required. This phase additionally extracts a trace-grounded PAY musical intermediate representation (IR), read-table evidence, and observed state transitions. It does not yet produce playable PAY machine code.

Load a .sid file to begin.

1 · Import PSID

Reads the binary locally. Static CFG uses official NMOS 6502 instructions. Bounded execution below supports PSID with normal subroutine INIT/PLAY; RSID and C64-specific IRQ hardware remain unsupported.

2 · Execute and trace 6502

Runs INIT then PLAY in a bounded offline 6502 interpreter. Captures runtime-only instructions, self-modifying code, concrete SID writes, effective memory reads (including indirect pattern fetches), actual branch destinations, and a per-frame 3-voice AY pitch preview. Not cycle-accurate and not full C64 hardware. No API key required.

No runtime trace yet. Static listing is still available.

PAY-00.5 · Musical state / pattern evidence (NEW)

Built automatically after a successful trace. Separates actual control-register changes from pitched-note candidates; summarizes repeated observable states without asserting that program loops have been proven. Captures executed indirect data reads and dynamic branch destinations.

Run a 6502 trace to extract PAY-IR.

Evidence is bounded to the frames executed. Exported IR is an analysis artifact, not playable Mockingboard code. A repeated sound state is not proof of an infinite source-code loop.

4 · GPT interpretation

Reasoning tokens count towards max_output_tokens. Default analysis budget is 12,000 tokens per batch; the original 2,800-token limit could expire before GPT emitted text. Unsupported reasoning settings are omitted for non-reasoning models.
