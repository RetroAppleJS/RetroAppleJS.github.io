1. Capture the register history

  1. Open RetroAppleJS with a Mockingboard in slot 4, with no other AY player running. Load the existing BASIC timing benchmark.
  2. Open the Mockingboard peripheral controls. Set history to at least 64 KB and click the coffee-cup history capture control to start recording.
  3. Run RUN for all three tests, or run CALL 24576, CALL 24579, and CALL 24582 individually in separate capture sessions.
  4. Click the coffee-cup control again to stop capture. Do not reset the Mockingboard before exporting.
  5. Export JSON using the console snippet below. The standard Mockingboard UI currently has a JSON export method, but its download button is not displayed.
Console command — exports currently visible Mockingboard
const b = [...document.querySelectorAll('button[title="Start/stop Mockingboard history capture"]')].find(x => x.getClientRects().length);
if (!b) throw Error('Open the Mockingboard controls first');
const match = b.getAttribute('onclick').match(/HASH2obj\((\d+)\)/);
if (!match) throw Error('Mockingboard card was not found');
apple2plus.hwObj().io.HASH2obj(Number(match[1])).downloadHistory();

In Chrome: View → Developer → JavaScript Console (or F12 → Console). Paste and press Enter. The download may be named mockingboard-slot5-history.json because older RetroAppleJS builds export an internal slot index rather than physical slot 4. If capturing was already stopped, running this code does not restart it.

Expected instruction-level reference

The reference is derived by executing the assembled 548-byte benchmark in an independent 6502 instruction model. It predicts relative CPU-cycle timestamps, aligned to the first AY0 R7=$3F write. Exact absolute CPU ticks are not expected to match across emulator runs.

Each run includes one R7=$3F setup write, one initial R8=$00, the measured R8 updates, and one final R8=$00 mute. Thus the full three-test capture should contain 67 + 67 + 35 = 169 AY writes, assuming no unrelated sound activity. MB-03's longer 57-cycle intervals reflect indexed-page crossing in the specific decoder fixture. The E1 delta values are parsed, not waited for; expected write intervals are instruction execution times, not encoded delays of 200 cycles.

Read-only browser verification. No modifications to RetroAppleJS's peripheral driver or the 6502 benchmark. A PASS requires exact chip/register/value order and timestamps within the chosen cycle tolerance. Emulator export remains the source of observed measurements.
