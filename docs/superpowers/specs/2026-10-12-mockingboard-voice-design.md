# Mockingboard voice device integration

User-authorized goal: turn the tested SSI263.js port into EMU_DEVICE_mockingboard_voice.js, integrate it beside EMU_DEVICE_mockingboard_audio.js, move the attached chip controls into a two-column peripheral controls popup, and combine AY core/history controls into one toolbox row.

Base: RetroAppleJS main c6498215487684bd20bee5e733085550eb550fe5. Keep AY chip objects internally and publish two default attached devices: audio output and SSI-263 voice. The voice class owns SSI synthesis; the card owns bus decoding, CPU timing, VIA IRQ routing and the common stereo PCM transport. Voice shares the existing sink rather than creating a second AudioContext.

Use separate logical and rendering SSI instances. CPU ticks advance the logical instance immediately for software requests/IRQ; timestamped writes and completion/powerdown events feed a bounded rendering queue so delayed PCM preserves earlier phonemes. Advance rendering and sample production on the card's existing mapped audio timeline. Keep raw CPU requests independent of output sample rate, buffering, muted playback and backend choice. Primary speech uses bit-6 slot-ROM write selects ($Cn40-$Cn7F, $CnC0-$CnFF) and VIA1 CA1. Keep current strict VIA address decoder; no extra VIA mirrors. Mockingboard slot speech reads remain floating bus, matching AppleWin's documented Mockingboard wiring; status is exposed through the device API and popup.

Voice internal sample rate defaults to 44,100 Hz and can be 22,050/44,100/48,000 Hz. Resample deterministic mono voice into the card's existing 22,050 Hz stereo frames, centered with bounded mixing. Do not reconfigure AY synthesis or the browser sink when voice PCM rate changes. CPU speed changes carry timestamped events; reset and backend replacement rebase the rendering transport while preserving live state where appropriate.

Popup: existing audio telemetry in the left column, SSI-263 controls in the right. Include duration, rate, 12-bit inflection, articulation, amplitude, filter, XCK, PCM sample rate, a phoneme audition, stop/powerdown and request/register status. CPU writes remain authoritative: sliders reflect registers, and manual controls perform actual register writes. Manual parameter edits preserve CTL and never wake a powered-down chip; audition explicitly enables a phoneme. The combined toolbox is one appbox flex row with AY backend, controls button, capture, history size/fill and FYM download.

Tests: preserved C++ PCM parity, voice power-up silence, live IRQ on VIA1 CA1, register aliases/select ranges, debugger read/write safety, audible finite mixed PCM, rendering before a later CPU completion, different audio chunk sizes and voice rates, muted progression, speed/backend/reset/unmount lifecycle, popup controls and one-row HTML, and existing repository tests.
