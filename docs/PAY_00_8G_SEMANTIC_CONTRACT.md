# PAY-00.8G — Executable semantic extension contract

## Scope and source

PAY-00.8G adds one **source-evidence-derived** operation to the `PAY_Semantic_Contract_v0.8F2` handoff:

- `PAY_First_Play_Executable_Extension_v0.8G`
- `operation.kind = first_play_voice_state_setup`
- An optional isolated command operation `optionalDiagnostic.kind = pitch_token_index_v1`.

Currently supported input: the exact Bomberland PSID with SHA-256 `65c3874b9f529c9adac45852f6e216eef2307a325051471d8b58290c38f71a68`, load `$1000`, INIT `$1000`, PLAY `$1003`. **Do not generalize this lowering to a different PSID.** The extension is an intentionally partial *research fixture*, not an approved full-song program.

The Interpreter owns evidence extraction, model interpretation, formalisation and source verification. The Compiler owns **100% deterministic** translation and refuses unsupported or mismatched operations. No third user-facing tool, no GPT calls from the compiler, no SID or AY frame history as compiler input.

### Reconciliation with source instructions

| Proven source mechanism | Source PC(s) | Typed semantic operation |
|---|---|---|
| First PLAY clears memory `$14AC..$14D5` | `$112D/$112F/$1132/$1133` | `zeroRegion(base,length,value)` |
| One-time init sets SID filter cutoff low `$D415=0` | `$1135` | `sidInit` |
| Source patched-state defaults set to zero | `$1138/$113B` | `patchedStateDefaults` |
| Three voice records at offsets 0, 7, 14 | `$1142/$1145/$1147/$114A/$114C..$115B` | `voices.offsets` and `voices.defaults` |
| Subtune-derived channel ordinal (`3*A+v`) | `$10F4/$10F5/$114C/$114D/$114E` | `voices.ordinal` |
| Source pitch code maps to note-table index | `$13CB/$1222/$1227/$1228/$122A` | Diagnostic `pitch_token_index_v1` |

The first PLAY computes ordinals `0/1/2` for subtune A=0, `3/4/5` for A=1, and `6/7/8` for A=2. The original reset region contains 42 bytes, independent of the three seven-byte voice records. The generated state is zero-page-free, uses no self-modifying instructions and writes one verified SID global-initialisation register.

### Proof checks and refusal policy

The deterministic Interpreter extension builder verifies:

- Exact source SHA-256, `player_entry` mechanism, candidate structural validation and `sourceLoopProven=false`.
- Original exact static instruction bytes and runtime execution evidence at the relevant PCs.
- Actual control-flow edges on the source first-PLAY clear path and three channel init paths.
- Candidate explicitly recognises first-PLAY control.
- The semantic operation fields are computed from source *operands* and not free-form GPT prose.

The Compiler *recomputes* the expected extension from the same source evidence. Modifying a field in the JSON, removing a referenced source instruction, changing its bytes or omitting proof blocks compilation. Unresolved sound mechanisms do not receive guessed implementations.

The older F3 backend had required the non-canonical alias `operand_read:$1129@PLAY` which was not generated by the full-report extractor. **00.8G fixes the requirement** to the canonical `operand_read:$1129@$1128` emitted by the Interpreter.

## Generated SID reference program

`Bomberland_PAY08G_SID_FIRST_PLAY.S` compiles to 346 bytes at `$1000`; `Bomberland_PAY08G_SID_FIRST_PLAY.sid` adds a 124-byte PSID v2 header and is 470 bytes total.

- INIT `$1000`, PLAY `$1003`, experimental STOP `$1006`.
- PLAY first-call setup, preserved state, then a placeholder regular path.
- A single SID register writer to `$D415`, value zero, during first-PLAY initialisation.
- `SID_REF_PITCH_INDEX` is a **manual test entry point**: supply `SR_TEST_TOKEN`, call the entry, inspect `SR_TEST_PITCH_VALID` and `SR_TEST_PITCH_INDEX`. This is not wired into the PLAY scheduler or audible SID voices.
- No original PSID engine, captured register-event history or AY waveform conversion is embedded.

The .sid header declares PAL and 50Hz VBI playback as **test harness assumptions**, not proof of the original source's interrupt/timing behaviour.

## Acceptance tests

`node tests/pay08g_first_play.test.cjs`:

- Executes original and regenerated 6502 on independent CPU instances for subtunes 0, 1, 2.
- Compares all 42 cleared source bytes, 12 visible voice-field defaults, two patch-controlled values, initial `$D415` write and first/steady-play counters.
- Tests 256 candidate pitch token values (93 valid tokens, `$60..$BC`), without a SID recording as input.
- Checks generated code does not modify itself, 9 refusal cases, deterministic byte repeatability, and parsability of the new PSID header.

`python tests/browser_08g.py`:

- Imports original 12MB complete report in the integrated Interpreter.
- Validates a corrected research candidate, exports a contract and confirms the extension is included.
- Compiles using the standalone Compiler, compares generated `.S`/`.sid` against the Node outputs and rejects a tampered extension.

The current passing tests establish **source-state equivalence for the first-PLAY slice only**. Not established: all SID register values on first frame, the source music-tick state, timers, notes, durations, gates, instruments, effect selection, pattern/whole-song loops, audio, or real C64 hardware timing.
